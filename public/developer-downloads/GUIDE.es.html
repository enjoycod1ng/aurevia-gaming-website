Elige tu lenguaje de desarrollo

Ejecuta estos ejemplos en tu backend. Muestran llamadas a la API y verificación de firmas; conéctalos a la sesión autenticada del jugador, los registros persistentes de lanzamiento y tu monedero transaccional. Los identificadores del código no cambian entre idiomas.

Antes de enviar un lanzamiento, guarda el símbolo elegido, el cuerpo exacto y la clave de idempotencia. Reintenta directamente esa solicitud guardada; no vuelvas a elegir el juego, generar una clave o modificar el jugador o dispositivo. El inicio rápido ilustra solo un lanzamiento nuevo.

// Node.js 20+ server-side helper. Never bundle this file with credentials into a browser.
import {createHmac, timingSafeEqual} from 'node:crypto';

export function verifyCallback(secret, rawBody, headers, operation, operatorId, now = Date.now() / 1000) {
  if (!secret || !operatorId || !['balance','debit','credit','rollback'].includes(operation)) throw new Error('Wallet verifier is not configured');
  const timestamp = headers['x-pp-timestamp'];
  const signature = headers['x-pp-signature'];
  if (!/^\d{1,12}$/.test(timestamp ?? '') || Math.abs(now - Number(timestamp)) > 300 || !/^[a-f0-9]{64}$/.test(signature ?? '')) {
    throw new Error('Invalid callback signature or timestamp');
  }
  const raw = Buffer.isBuffer(rawBody) ? rawBody : Buffer.from(rawBody, 'utf8');
  const expected = createHmac('sha256', secret).update(timestamp + '.').update(raw).digest();
  if (!timingSafeEqual(expected, Buffer.from(signature, 'hex'))) throw new Error('Invalid callback signature');
  const payload = JSON.parse(raw.toString('utf8'));
  if (typeof payload?.request_id !== 'string' || !payload.request_id || payload.request_id !== headers['x-pp-request-id'] || payload.operator_id !== operatorId || payload.transaction_type !== operation) {
    throw new Error('Callback identity mismatch');
  }
  return payload;
}

export async function providerRequest(baseUrl, apiKey, method, path, body, idempotencyKey) {
  const base = new URL(baseUrl.endsWith('/') ? baseUrl : baseUrl + '/');
  if (base.protocol !== 'https:') throw new Error('Provider URL must use HTTPS');
  if (!path.startsWith('api/provider/v1/')) throw new Error('Invalid provider path');
  const headers = {'X-Provider-API-Key': apiKey, 'Accept': 'application/json'};
  if (body !== undefined) headers['Content-Type'] = 'application/json';
  if (idempotencyKey) headers['Idempotency-Key'] = idempotencyKey;
  const response = await fetch(new URL(path, base), {
    method, headers, body: body === undefined ? undefined : JSON.stringify(body),
    redirect: 'error', signal: AbortSignal.timeout(15000),
  });
  const result = await response.json();
  if (!response.ok) {
    const error = new Error(result.message ?? 'Provider request failed');
    error.status = response.status;
    error.code = result.error;
    error.retryAfter = response.headers.get('retry-after');
    throw error;
  }
  return result.data;
}

export function launchGame(baseUrl, apiKey, authenticatedPlayerId, returnUrl, idempotencyKey, symbol = 'wildframes', device = 'desktop') {
  if (!idempotencyKey) throw new Error('Persist one idempotency key per launch attempt and reuse it on retries');
  if (!['desktop','mobile'].includes(device)) throw new Error('Device must be desktop or mobile');
  return providerRequest(baseUrl, apiKey, 'POST', 'api/provider/v1/launch-url', {
    symbol, external_player_id: authenticatedPlayerId, currency: 'EUR', lang: 'en', device, return_url: returnUrl,
  }, idempotencyKey);
}

<?php
declare(strict_types=1);
// PHP 8+ with cURL. Server-side only; load credentials from your secret store.

function verifyCallback(string $secret, string $rawBody, array $headers, string $operation, string $operatorId, ?int $now = null): array {
    if ($secret === '' || $operatorId === '' || !in_array($operation, ['balance','debit','credit','rollback'], true)) throw new RuntimeException('Wallet verifier is not configured');
    $headers = array_change_key_case($headers, CASE_LOWER);
    $timestamp = $headers['x-pp-timestamp'] ?? '';
    $signature = $headers['x-pp-signature'] ?? '';
    if (!preg_match('/^\d{1,12}$/D', $timestamp) || abs(($now ?? time()) - (int)$timestamp) > 300 || !preg_match('/^[a-f0-9]{64}$/D', $signature)) {
        throw new RuntimeException('Invalid callback signature or timestamp');
    }
    if (!hash_equals(hash_hmac('sha256', $timestamp . '.' . $rawBody, $secret), $signature)) {
        throw new RuntimeException('Invalid callback signature');
    }
    $payload = json_decode($rawBody, true, 512, JSON_THROW_ON_ERROR);
    if (!is_string($payload['request_id'] ?? null) || $payload['request_id'] === '' || ($payload['request_id'] ?? null) !== ($headers['x-pp-request-id'] ?? null)
        || ($payload['operator_id'] ?? null) !== $operatorId || ($payload['transaction_type'] ?? null) !== $operation) {
        throw new RuntimeException('Callback identity mismatch');
    }
    return $payload;
}

function providerRequest(string $baseUrl, string $apiKey, string $method, string $path, ?array $body = null, ?string $idempotencyKey = null): array {
    if (parse_url($baseUrl, PHP_URL_SCHEME) !== 'https' || !str_starts_with($path, 'api/provider/v1/')) {
        throw new InvalidArgumentException('Invalid provider HTTPS URL or API path');
    }
    if (strpbrk($apiKey . ($idempotencyKey ?? ''), "\r\n") !== false) throw new InvalidArgumentException('Invalid header');
    $headers = ['X-Provider-API-Key: ' . $apiKey, 'Accept: application/json'];
    if ($body !== null) $headers[] = 'Content-Type: application/json';
    if ($idempotencyKey !== null) $headers[] = 'Idempotency-Key: ' . $idempotencyKey;
    $handle = curl_init(rtrim($baseUrl, '/') . '/' . $path);
    curl_setopt_array($handle, [CURLOPT_RETURNTRANSFER => true, CURLOPT_CUSTOMREQUEST => $method,
        CURLOPT_HTTPHEADER => $headers, CURLOPT_CONNECTTIMEOUT => 5, CURLOPT_TIMEOUT => 15,
        CURLOPT_FOLLOWLOCATION => false, CURLOPT_SSL_VERIFYPEER => true, CURLOPT_SSL_VERIFYHOST => 2]);
    if ($body !== null) curl_setopt($handle, CURLOPT_POSTFIELDS, json_encode($body, JSON_THROW_ON_ERROR));
    $raw = curl_exec($handle);
    $status = curl_getinfo($handle, CURLINFO_RESPONSE_CODE);
    $failed = $raw === false;
    $errorNumber = curl_errno($handle);
    curl_close($handle);
    if ($failed) throw new RuntimeException('Provider connection failed (cURL ' . $errorNumber . '); retry launch with the same idempotency key');
    $result = json_decode($raw, true, 512, JSON_THROW_ON_ERROR);
    if ($status < 200 || $status >= 300) throw new RuntimeException($result['message'] ?? 'Provider request failed', $status);
    return $result['data'];
}

function launchGame(string $baseUrl, string $apiKey, string $authenticatedPlayerId, string $returnUrl, string $idempotencyKey, string $symbol = 'wildframes', string $device = 'desktop'): array {
    if ($idempotencyKey === '') throw new InvalidArgumentException('Persist an idempotency key before launching');
    if (!in_array($device, ['desktop','mobile'], true)) throw new InvalidArgumentException('Device must be desktop or mobile');
    return providerRequest($baseUrl, $apiKey, 'POST', 'api/provider/v1/launch-url', [
        'symbol' => $symbol, 'external_player_id' => $authenticatedPlayerId, 'currency' => 'EUR',
        'lang' => 'en', 'device' => $device, 'return_url' => $returnUrl,
    ], $idempotencyKey);
}

// .NET 8+. Server-side only. Reuse this client; obtain credentials from a secret store.
using System.Net;
using System.Security.Cryptography;
using System.Text;
using System.Text.Json;
using System.Text.RegularExpressions;

public sealed class AureviaProvider : IDisposable
{
    private readonly HttpClient http;
    private readonly Uri baseUri;
    private readonly string apiKey;

    public AureviaProvider(string baseUrl, string apiKey)
    {
        baseUri = new Uri(baseUrl.TrimEnd('/') + "/");
        if (baseUri.Scheme != "https" || baseUri.UserInfo != "" || baseUri.Query != "" || baseUri.Fragment != "")
            throw new ArgumentException("Use the assigned HTTPS provider base URL.");
        if (string.IsNullOrEmpty(apiKey) || apiKey.Contains('\r') || apiKey.Contains('\n'))
            throw new ArgumentException("Invalid API key header.");
        this.apiKey = apiKey;
        http = new HttpClient(new HttpClientHandler { AllowAutoRedirect = false, UseCookies = false })
            { Timeout = TimeSpan.FromSeconds(15) };
    }

    public async Task<JsonElement> RequestAsync(HttpMethod method, string path, object? body = null,
        string? idempotencyKey = null, CancellationToken cancellationToken = default)
    {
        if (!path.StartsWith("api/provider/v1/", StringComparison.Ordinal) || path.Contains("..") || path.Contains('\\'))
            throw new ArgumentException("Invalid provider path.");
        using var request = new HttpRequestMessage(method, new Uri(baseUri, path));
        request.Headers.Add("X-Provider-API-Key", apiKey);
        request.Headers.Add("Accept", "application/json");
        if (idempotencyKey != null) request.Headers.Add("Idempotency-Key", idempotencyKey);
        if (body != null) request.Content = new StringContent(JsonSerializer.Serialize(body), Encoding.UTF8, "application/json");
        using var response = await http.SendAsync(request, cancellationToken);
        if (!response.IsSuccessStatusCode)
            throw new ProviderException(response.StatusCode, response.Headers.RetryAfter?.ToString());
        using var document = JsonDocument.Parse(await response.Content.ReadAsStringAsync(cancellationToken));
        return document.RootElement.GetProperty("data").Clone();
    }

    public Task<JsonElement> LaunchAsync(string authenticatedPlayerId, string returnUrl, string persistedKey,
        string symbol = "wildframes", string device = "desktop", CancellationToken cancellationToken = default)
    {
        if (string.IsNullOrEmpty(persistedKey)) throw new ArgumentException("Persist a key before launching; reuse it with the exact body on retries.");
        if (device != "desktop" && device != "mobile") throw new ArgumentException("Invalid device.");
        return RequestAsync(HttpMethod.Post, "api/provider/v1/launch-url", new {
            symbol, external_player_id = authenticatedPlayerId, currency = "EUR", lang = "en", device, return_url = returnUrl
        }, persistedKey, cancellationToken);
    }

    public static JsonElement VerifyCallback(string secret, byte[] rawBody, string timestamp, string signature,
        string requestId, string operation, string operatorId, long? now = null)
    {
        if (string.IsNullOrEmpty(secret) || string.IsNullOrEmpty(operatorId) ||
            !new[] { "balance", "debit", "credit", "rollback" }.Contains(operation))
            throw new ArgumentException("Wallet verifier is not configured.");
        if (!Regex.IsMatch(timestamp, @"\A[0-9]{1,12}\z") ||
            Math.Abs((now ?? DateTimeOffset.UtcNow.ToUnixTimeSeconds()) - long.Parse(timestamp)) > 300 ||
            !Regex.IsMatch(signature, @"\A[a-f0-9]{64}\z")) throw new CryptographicException("Invalid signature or timestamp.");
        using var hmac = IncrementalHash.CreateHMAC(HashAlgorithmName.SHA256, Encoding.UTF8.GetBytes(secret));
        hmac.AppendData(Encoding.ASCII.GetBytes(timestamp + "."));
        hmac.AppendData(rawBody);
        if (!CryptographicOperations.FixedTimeEquals(hmac.GetHashAndReset(), Convert.FromHexString(signature)))
            throw new CryptographicException("Invalid signature.");
        using var document = JsonDocument.Parse(rawBody);
        var payload = document.RootElement;
        if (string.IsNullOrEmpty(requestId) || payload.GetProperty("request_id").GetString() != requestId ||
            payload.GetProperty("operator_id").GetString() != operatorId || payload.GetProperty("transaction_type").GetString() != operation)
            throw new InvalidOperationException("Callback identity mismatch.");
        return payload.Clone();
    }

    public void Dispose() => http.Dispose();
}

public sealed class ProviderException(HttpStatusCode status, string? retryAfter) : Exception($"Provider HTTP {(int)status}")
{
    public HttpStatusCode Status { get; } = status;
    public string? RetryAfter { get; } = retryAfter;
}

// Java 17+ and Jackson (see pom.xml). Backend only; never expose API keys to a browser.
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import java.net.URI;
import java.net.http.*;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.time.Duration;
import java.time.Instant;
import java.util.*;
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;

public final class AureviaProvider {
    private static final ObjectMapper JSON = new ObjectMapper();
    private final HttpClient http = HttpClient.newBuilder().followRedirects(HttpClient.Redirect.NEVER)
        .connectTimeout(Duration.ofSeconds(5)).build();
    private final URI base;
    private final String key;

    public AureviaProvider(String baseUrl, String apiKey) {
        base = URI.create(baseUrl.replaceAll("/+$", "") + "/");
        if (!"https".equals(base.getScheme()) || base.getHost() == null || base.getUserInfo() != null ||
            base.getQuery() != null || base.getFragment() != null) throw new IllegalArgumentException("Use the assigned HTTPS base URL.");
        if (apiKey == null || apiKey.isEmpty() || apiKey.contains("\r") || apiKey.contains("\n"))
            throw new IllegalArgumentException("Invalid API key header.");
        key = apiKey;
    }

    public JsonNode request(String method, String path, Object body, String persistedKey) throws Exception {
        if (!path.startsWith("api/provider/v1/") || path.contains("..") || path.contains("\\"))
            throw new IllegalArgumentException("Invalid provider path.");
        var builder = HttpRequest.newBuilder(base.resolve(path)).timeout(Duration.ofSeconds(15))
            .header("X-Provider-API-Key", key).header("Accept", "application/json");
        if (persistedKey != null) builder.header("Idempotency-Key", persistedKey);
        var publisher = HttpRequest.BodyPublishers.noBody();
        if (body != null) {
            builder.header("Content-Type", "application/json");
            publisher = HttpRequest.BodyPublishers.ofString(JSON.writeValueAsString(body), StandardCharsets.UTF_8);
        }
        var response = http.send(builder.method(method, publisher).build(), HttpResponse.BodyHandlers.ofString(StandardCharsets.UTF_8));
        if (response.statusCode() < 200 || response.statusCode() >= 300)
            throw new ProviderException(response.statusCode(), response.headers().firstValue("Retry-After").orElse(null));
        return JSON.readTree(response.body()).required("data");
    }

    public JsonNode launch(String authenticatedPlayerId, String returnUrl, String persistedKey, String symbol, String device) throws Exception {
        if (persistedKey == null || persistedKey.isEmpty()) throw new IllegalArgumentException("Persist the launch key before sending; reuse it on retries.");
        if (!Set.of("desktop", "mobile").contains(device)) throw new IllegalArgumentException("Invalid device.");
        return request("POST", "api/provider/v1/launch-url", Map.of("symbol", symbol,
            "external_player_id", authenticatedPlayerId, "currency", "EUR", "lang", "en", "device", device,
            "return_url", returnUrl), persistedKey);
    }

    public static JsonNode verifyCallback(String secret, byte[] rawBody, String timestamp, String signature,
        String requestId, String operation, String operatorId, long now) throws Exception {
        if (secret == null || secret.isEmpty() || operatorId == null || operatorId.isEmpty() ||
            !Set.of("balance", "debit", "credit", "rollback").contains(operation)) throw new IllegalArgumentException("Verifier is not configured.");
        if (timestamp == null || !timestamp.matches("[0-9]{1,12}") ||
            Math.abs(now - Long.parseLong(timestamp)) > 300 || signature == null || !signature.matches("[a-f0-9]{64}"))
            throw new SecurityException("Invalid signature or timestamp.");
        var mac = Mac.getInstance("HmacSHA256");
        mac.init(new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
        mac.update((timestamp + ".").getBytes(StandardCharsets.US_ASCII));
        if (!MessageDigest.isEqual(mac.doFinal(rawBody), HexFormat.of().parseHex(signature))) throw new SecurityException("Invalid signature.");
        var payload = JSON.readTree(rawBody);
        if (requestId == null || requestId.isEmpty() || !payload.path("request_id").isTextual() ||
            !requestId.equals(payload.path("request_id").asText()) || !operatorId.equals(payload.path("operator_id").asText()) ||
            !operation.equals(payload.path("transaction_type").asText())) throw new SecurityException("Callback identity mismatch.");
        return payload;
    }

    public static final class ProviderException extends Exception {
        public final int status;
        public final String retryAfter;
        ProviderException(int status, String retryAfter) {
            super("Provider HTTP " + status); this.status = status; this.retryAfter = retryAfter;
        }
    }
}

1. Comprende la integración

Tu backend autentica al jugador, consulta los juegos asignados y solicita una URL de lanzamiento. Tu frontend abre esa URL. Tu monedero mantiene el saldo autorizado e implementa cuatro callbacks HTTPS: balance, debit, credit y rollback. El juego alojado gestiona sus recursos y su protocolo nativo.

La versión 1.0.1 es un entorno de pruebas con nueve juegos y dos monederos de operadores simulados. Usa solo fondos simulados. Actualmente admite EUR y juegos en inglés, con cuatro sesiones simultáneas en total y dos por operador. El acceso de clientes a producción requiere validación y activación independientes. La documentación en español o portugués no habilita esos idiomas en la API del juego. Este servicio integra el runtime del VPS; no es la API oficial para desarrolladores de Play’n GO.

2. Configura tu backend

Usa https://aureviagaming.com/playngo-sandbox como PROVIDER_BASE_URL. Guarda OPERATOR_API_KEY en el almacén de secretos del servidor. Envía x-provider-api-key en cada solicitud, o Authorization: Bearer, usando solo un método. Nunca pongas claves en URLs, código frontend o registros. La identidad del operador se obtiene de la clave; omite operator_id en las solicitudes al proveedor. El secreto de firma del monedero es una credencial independiente.

Durante la incorporación, facilita los orígenes web, las URLs HTTPS de retorno o lobby, las URLs base de callbacks, las monedas solicitadas y un contacto técnico. Las credenciales y la configuración son independientes en cada entorno. Tu servidor necesita HTTPS/JSON, relojes sincronizados, verificación HMAC del cuerpo original, registros persistentes y actualizaciones atómicas de saldos decimales. Las plataformas alojadas deben permitir un adaptador personalizado. Las webs estáticas necesitan backend; las apps nativas necesitan una integración probada de navegador o WebView.

3. Consulta los juegos asignados

GET /api/provider/v1/games?provider_id=playngo devuelve data.items con los juegos asignados y habilitados para tu operador. GET /api/provider/v1/games/{symbol} devuelve un juego. Usa los símbolos del catálogo y tolera campos de respuesta desconocidos. La disponibilidad no garantiza todas las funciones, idiomas o apuestas. El contrato v1 no incluye un endpoint para asignar tiradas gratis promocionales.

Los símbolos preparados son wildframes, honeyrush, moonprincess, wheelofmictlan, secretofdead, legacyofegypt, hugosadventure, trollhunters2 y demon. honeyrush corresponde al Honey Rush original; Honey Rush Black & Yellow es otro título. No fijes el número de juegos del catálogo en tu integración.

4. Inicia el juego para el jugador autenticado

POST /api/provider/v1/launch-url requiere Idempotency-Key. El cuerpo JSON requiere symbol, external_player_id, currency y return_url. El campo opcional lang usa en por defecto; device es desktop o mobile, con desktop por defecto. Usa EUR, un símbolo asignado y una URL HTTPS de retorno aprobada en este entorno. Los idiomas de juego no admitidos se rechazan. Obtén external_player_id de la sesión autenticada del servidor; nunca confíes directamente en un ID enviado por el navegador.

Los IDs de jugador son cadenas opacas de 1–128 caracteres y conservan mayúsculas, Unicode y espacios iniciales o finales. No los recortes ni normalices para convertirlos en otra identidad. Conserva exactamente session_id, round_id, transaction_id y request_id. La versión 1.0.0 recortaba los IDs; los reintentos antiguos con espacios pueden devolver 409. Concilia la sesión original antes de crear intencionadamente un nuevo lanzamiento.

Guarda una clave de lanzamiento y el cuerpo exacto antes de enviar. Los reintentos idénticos devuelven la respuesta y caducidad originales; un cuerpo distinto con la misma clave devuelve 409 idempotency_conflict. Conserva las claves al menos 24 horas. Tras consumir o caducar el ticket, un nuevo lanzamiento intencional necesita una clave nueva. Un timeout no autoriza a generar otra clave.

{
  "symbol": "wildframes",
  "external_player_id": "player-123",
  "currency": "EUR",
  "lang": "en",
  "device": "desktop",
  "return_url": "https://client.example/lobby"
}

5. Abre y cierra el juego correctamente

Un lanzamiento correcto devuelve data.launch_url, session_id y expires_at. Entrega solo la URL al navegador autenticado correspondiente y ábrela pronto mediante redirección o iframe. El ticket es de un solo uso y dura 60 segundos. Usa título en el iframe, permiso de pantalla completa, política no-referrer y altura adaptable. Tu CSP frame-src debe permitir el origen del juego; el proveedor también debe aprobar tu origen para incrustarlo. Prueba móviles y cookies de terceros bloqueadas. CORS no controla la incrustación de iframes.

Una sesión dura hasta 30 minutos de inactividad o cuatro horas en total. Una reconexión de red dentro de la misma página usa una credencial de sesión independiente. Recargar la página, reiniciar el navegador o reabrir una URL copiada requiere otro lanzamiento. Cierra la sesión anterior con POST /api/provider/v1/sessions/{session_id}/close y solicita una nueva con otra clave. El cierre puede repetirse y bloquea nuevas jugadas sin impedir pagos o reembolsos aceptados. Los tickets no usados reservan capacidad hasta caducar. Volver al lobby no demuestra que la liquidación terminó.

<iframe id="game" title="Game" allow="fullscreen" allowfullscreen
  referrerpolicy="no-referrer"
  style="width:100%;height:100dvh;border:0"></iframe>

6. Verifica los callbacks del monedero

Implementa POST /balance, /debit, /credit y /rollback bajo la URL base configurada de tu monedero. El proveedor envía content-type: application/json, x-pp-request-id, x-pp-timestamp (segundos Unix) y x-pp-signature. Calcula HMAC-SHA256 hexadecimal en minúsculas sobre ASCII(timestamp) + un punto + el cuerpo UTF-8 original exacto, usando el secreto del monedero. Compara en tiempo constante y rechaza desfases superiores a 300 segundos. Conserva los bytes antes de cualquier middleware JSON; analizar y serializar de nuevo cambia la firma.

Tras verificar la firma, analiza el JSON y exige que el ID de solicitud de la cabecera coincida con request_id, operator_id con tu operador configurado y transaction_type con el endpoint. Valida la titularidad del jugador y sesión y todo el esquema antes de acceder al libro contable. Los reintentos usan nuevos timestamps, firmas e IDs de solicitud, conservando el ID de transacción y los campos financieros. El fixture determinista descargable prueba los cuatro lenguajes sin contactar un monedero.

HMAC-SHA256(wallet_secret, ASCII(timestamp) + "." + raw_request_body)

7. Aplica el contrato del monedero

Los importes y saldos son cadenas decimales con exactamente dos cifras fraccionarias, como "2.00". Usa unidades menores enteras o un tipo decimal; nunca aritmética binaria de coma flotante. Las monedas habilitadas usan dos decimales, sin conversión de divisas automática. Los campos comunes son operator_id, player_id, session_id, game_symbol, currency, request_id, transaction_id, transaction_type, action_type y amount. El esquema OpenAPI define los tipos y límites exactos.

Balance usa amount "0.00" y action_type balance, omitiendo campos de ronda. Debit requiere importe positivo, round_id y round_closed false. Credit requiere round_id y round_closed, permite cero y cierra la ronda con el crédito final. Rollback requiere importe positivo, round_closed true y original_transaction_id. Varias etapas o tiradas gratis pueden compartir ronda; deduplica por transacción, nunca solo por ronda. action_type es descriptivo y no sustituye transaction_type.

Devuelve HTTP 200 con success true, el saldo autorizado, currency y transaction_id coincidentes. Los rechazos de negocio válidos usan HTTP 200 con success false y errores como insufficient_funds, unknown_player, currency_mismatch, player_blocked o transaction_cancelled. Usa 401 para firmas inválidas o timestamps antiguos; 403 para titularidad inválida; 400 para datos inválidos; 409 para identidades de transacción en conflicto; 503 para fallos temporales. Devuelve JSON UTF-8 sin comprimir en cinco segundos, con un máximo de 65.536 bytes; nunca una página HTML de error.

{"success":true,"balance":"98.00","currency":"EUR","transaction_id":"txn_debit_example_01"}

8. Garantiza un único efecto financiero

Dentro de cada entorno y operador, registra un transaction_id único con una huella del jugador, sesión, juego, ronda, tipo, acción, moneda, importe, cierre de ronda y referencia al débito original. Excluye IDs de entrega y timestamps. En UNA transacción de base de datos: registra o comprueba el ID, bloquea o actualiza atómicamente el monedero, valida fondos y moneda, guarda el asiento y la respuesta inmutable, y confirma. Los duplicados simultáneos deben obtener el mismo resultado guardado. Guarda también los rechazos definitivos; cambiar campos financieros con el mismo ID produce idempotency_conflict.

Un callback financiero exitoso repetido devuelve su saldo y respuesta ORIGINALES guardados, aunque otras transacciones hayan cambiado el monedero. Nunca lo apliques dos veces. Otra solicitud balance consulta el saldo actual. Conserva los registros de deduplicación y cancelación mientras puedan existir reintentos o conciliación; los registros sin resolver no deben caducar. La conservación y el archivo se acuerdan durante la incorporación.

9. Gestiona cancelaciones y recuperación

Rollback referencia el débito original mediante original_transaction_id. El importe, moneda y titularidad deben coincidir. Si existe y no está cancelado, reembolsa una vez; si ya está cancelado, responde con éxito sin otro reembolso. Si falta, guarda una marca de cancelación y responde con éxito sin cambiar fondos; rechaza cualquier débito posterior con ese ID. Serializa tanto el ID de rollback como el del débito original para evitar reembolsos dobles mediante intentos distintos. Nunca reviertas un crédito no relacionado.

Una respuesta desconocida puede significar que el monedero confirmó antes de fallar la conexión. Detén el juego ante un débito desconocido y resuelve la misma transacción o cancélala mediante rollback. Mantén créditos y reembolsos pendientes hasta confirmarlos; los reintentos conservan sus IDs. El proveedor usa espera progresiva con variación (aproximadamente 1, 5, 15 y luego 60 segundos), revisada cada cinco segundos, con obligaciones persistentes. Sigue liquidando créditos y reembolsos aceptados tras cerrar el navegador o caducar la sesión. No se cancela una ronda revelada pagadera para evitar pagarla. Las rondas aceptadas cerradas se cobran automáticamente tras dos minutos de inactividad; gamble está deshabilitado en esta versión.

10. Consulta sesiones y transacciones

GET /api/provider/v1/transactions?limit=50 lista las transacciones de tu operador de más reciente a más antigua. El tamaño de página es de 1–100. Envía data.next_cursor sin modificar como cursor para la siguiente página; el límite del cursor es 2.048 caracteres. GET /api/provider/v1/transactions/{transaction_id} devuelve operación, importe, moneda, IDs de ronda y sesión, estado, número de intentos y último error. GET /api/provider/v1/sessions/{session_id} devuelve metadatos con control de titularidad. Codifica los IDs opacos como segmentos individuales de URL.

pending, sending y unknown siguen resolviéndose: no crees transacciones financieras de sustitución. success está confirmado por el monedero; rejected es un rechazo definitivo de débito o saldo; cancelled indica un débito sin resolver cancelado por rollback. Un débito correcto reembolsado conserva success con cancelled_by_rollback y un rollback exitoso independiente. Los créditos o reembolsos rechazados siguen pendientes de recuperación y atención del operador.

11. Gestiona errores y capacidad

Los errores del proveedor contienen success false, error, message y request_id. Ante 400/422 corrige los datos o moneda e idioma no admitidos; 401 corrige credenciales; 403 revisa permisos del operador, juego y origen; 404 actualiza el catálogo o comprueba el recurso; 409 concilia la clave de lanzamiento en conflicto. Ante 429 respeta Retry-After. Ante 502/503 o timeouts de red, espera y reintenta con la clave y cuerpo originales guardados. Las solicitudes GET pueden repetirse. Conserva IDs de solicitud sin secretos para soporte.

El límite del entorno es de 60 solicitudes al proveedor por minuto y operador, excluyendo juego y callbacks salientes. Los cuerpos admiten 65.536 bytes y diez segundos (413 por tamaño, 408 por timeout). 503 capacity_reached y 503 maintenance incluyen Retry-After: 5; espera y repite la misma clave. El mantenimiento bloquea nuevas apuestas mientras continúan pagos y reembolsos aceptados. Cuatro sesiones totales y dos por operador son límites de admisión, no una capacidad de gran volumen. Una página de verificación de navegador no es una respuesta API: repórtala con su ID en vez de desactivar TLS o exponer credenciales en el navegador.

12. Prueba antes de activar clientes

Ejecuta primero las pruebas de firma sin conexión incluidas. Después prueba catálogo y autenticación, aislamiento de jugadores, caducidad y reutilización de lanzamientos, iframes en escritorio y móvil, todos los callbacks, duplicados simultáneos, timeout tras confirmar, rollback antes del débito, fondos insuficientes, recuperación de créditos y reconexión durante funciones. Concilia los débitos aceptados con créditos finales o cancelaciones confirmadas. Un health check o demo funcional no certifica un monedero cliente.

La herramienta reanudable wallet-conformance.mjs requiere Node.js 20+, un jugador de pruebas dedicado e inactivo y al menos EUR 1.00 simulados. Copia su configuración de ejemplo a un archivo privado y ejecútala con un diario privado. Sus 17 comprobaciones dejan un cambio neto de saldo cero al completarse. Tras un fallo de conexión, reanuda con la MISMA configuración y diario; nunca borres el diario ni cambies IDs para reintentar. Mantén secretos, diarios financieros y fondos reales fuera del paquete público. Las demos públicas usan saldos de visitantes aislados que comienzan con 10.000,00 EUR. Son independientes de los jugadores de integración y las pruebas de aceptación; el laboratorio retirado requiere acceso del personal.

node examples/test-examples.mjs
php examples/test-examples.php

13. Versionado y soporte

/api/provider/v1 y playngo-callback-v1 identifican los contratos; la versión de software 1.0.1 es independiente. Pueden añadirse campos opcionales y juegos; ignora campos de respuesta desconocidos y actualiza el catálogo. Los cambios incompatibles de campos, firma o semántica financiera requieren otro contrato versionado y una migración acordada. Conserva OpenAPI aceptado, diario de validación, orígenes, monedas, juegos y límites asignados y resultados de navegador con tu versión. Las credenciales de pruebas nunca se vuelven de producción cambiando la URL.

Para soporte técnico, facilita entorno, hora UTC, símbolo del juego, IDs de sesión, ronda y transacción, ID de solicitud del proveedor y errores sin secretos por el canal acordado. Nunca compartas claves API, secretos de firma o URLs activas de lanzamiento. Las alertas del operador y la activación de producción son pasos independientes de incorporación.
