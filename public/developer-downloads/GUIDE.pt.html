Execute estes exemplos no backend. Eles demonstram chamadas à API e verificação de assinaturas; conecte-os à sessão autenticada do jogador, aos registros persistentes de abertura e à carteira transacional. Os identificadores de código não mudam entre idiomas.

Antes de solicitar a abertura, salve o símbolo escolhido, o corpo exato e a chave de idempotência. Repita diretamente essa solicitação salva; não selecione o jogo novamente, gere outra chave ou altere jogador e dispositivo. O início rápido demonstra apenas uma nova abertura.

// Node.js 20+ server-side helper. Never bundle this file with credentials into a browser.
import {createHmac, timingSafeEqual} from 'node:crypto';

export function verifyCallback(secret, rawBody, headers, operation, operatorId, now = Date.now() / 1000) {
  if (!secret || !operatorId || !['balance','debit','credit','rollback'].includes(operation)) throw new Error('Wallet verifier is not configured');
  const timestamp = headers['x-pp-timestamp'];
  const signature = headers['x-pp-signature'];
  if (!/^\d{1,12}$/.test(timestamp ?? '') || Math.abs(now - Number(timestamp)) > 300 || !/^[a-f0-9]{64}$/.test(signature ?? '')) {
    throw new Error('Invalid callback signature or timestamp');
  }
  const raw = Buffer.isBuffer(rawBody) ? rawBody : Buffer.from(rawBody, 'utf8');
  const expected = createHmac('sha256', secret).update(timestamp + '.').update(raw).digest();
  if (!timingSafeEqual(expected, Buffer.from(signature, 'hex'))) throw new Error('Invalid callback signature');
  const payload = JSON.parse(raw.toString('utf8'));
  if (typeof payload?.request_id !== 'string' || !payload.request_id || payload.request_id !== headers['x-pp-request-id'] || payload.operator_id !== operatorId || payload.transaction_type !== operation) {
    throw new Error('Callback identity mismatch');
  }
  return payload;
}

export async function providerRequest(baseUrl, apiKey, method, path, body, idempotencyKey) {
  const base = new URL(baseUrl.endsWith('/') ? baseUrl : baseUrl + '/');
  if (base.protocol !== 'https:') throw new Error('Provider URL must use HTTPS');
  if (!path.startsWith('api/provider/v1/')) throw new Error('Invalid provider path');
  const headers = {'X-Provider-API-Key': apiKey, 'Accept': 'application/json'};
  if (body !== undefined) headers['Content-Type'] = 'application/json';
  if (idempotencyKey) headers['Idempotency-Key'] = idempotencyKey;
  const response = await fetch(new URL(path, base), {
    method, headers, body: body === undefined ? undefined : JSON.stringify(body),
    redirect: 'error', signal: AbortSignal.timeout(15000),
  });
  const result = await response.json();
  if (!response.ok) {
    const error = new Error(result.message ?? 'Provider request failed');
    error.status = response.status;
    error.code = result.error;
    error.retryAfter = response.headers.get('retry-after');
    throw error;
  }
  return result.data;
}

export function launchGame(baseUrl, apiKey, authenticatedPlayerId, returnUrl, idempotencyKey, symbol = 'wildframes', device = 'desktop') {
  if (!idempotencyKey) throw new Error('Persist one idempotency key per launch attempt and reuse it on retries');
  if (!['desktop','mobile'].includes(device)) throw new Error('Device must be desktop or mobile');
  return providerRequest(baseUrl, apiKey, 'POST', 'api/provider/v1/launch-url', {
    symbol, external_player_id: authenticatedPlayerId, currency: 'EUR', lang: 'en', device, return_url: returnUrl,
  }, idempotencyKey);
}

// enforce the (operator_id,transaction_id) unique key, apply the ledger mutation,
// and store the immutable response in the same database transaction.

<?php
declare(strict_types=1);
// PHP 8+ with cURL. Server-side only; load credentials from your secret store.

function verifyCallback(string $secret, string $rawBody, array $headers, string $operation, string $operatorId, ?int $now = null): array {
    if ($secret === '' || $operatorId === '' || !in_array($operation, ['balance','debit','credit','rollback'], true)) throw new RuntimeException('Wallet verifier is not configured');
    $headers = array_change_key_case($headers, CASE_LOWER);
    $timestamp = $headers['x-pp-timestamp'] ?? '';
    $signature = $headers['x-pp-signature'] ?? '';
    if (!preg_match('/^\d{1,12}$/D', $timestamp) || abs(($now ?? time()) - (int)$timestamp) > 300 || !preg_match('/^[a-f0-9]{64}$/D', $signature)) {
        throw new RuntimeException('Invalid callback signature or timestamp');
    }
    if (!hash_equals(hash_hmac('sha256', $timestamp . '.' . $rawBody, $secret), $signature)) {
        throw new RuntimeException('Invalid callback signature');
    }
    $payload = json_decode($rawBody, true, 512, JSON_THROW_ON_ERROR);
    if (!is_string($payload['request_id'] ?? null) || $payload['request_id'] === '' || ($payload['request_id'] ?? null) !== ($headers['x-pp-request-id'] ?? null)
        || ($payload['operator_id'] ?? null) !== $operatorId || ($payload['transaction_type'] ?? null) !== $operation) {
        throw new RuntimeException('Callback identity mismatch');
    }
    return $payload;
}

function providerRequest(string $baseUrl, string $apiKey, string $method, string $path, ?array $body = null, ?string $idempotencyKey = null): array {
    if (parse_url($baseUrl, PHP_URL_SCHEME) !== 'https' || !str_starts_with($path, 'api/provider/v1/')) {
        throw new InvalidArgumentException('Invalid provider HTTPS URL or API path');
    }
    if (strpbrk($apiKey . ($idempotencyKey ?? ''), "\r\n") !== false) throw new InvalidArgumentException('Invalid header');
    $headers = ['X-Provider-API-Key: ' . $apiKey, 'Accept: application/json'];
    if ($body !== null) $headers[] = 'Content-Type: application/json';
    if ($idempotencyKey !== null) $headers[] = 'Idempotency-Key: ' . $idempotencyKey;
    $handle = curl_init(rtrim($baseUrl, '/') . '/' . $path);
    curl_setopt_array($handle, [CURLOPT_RETURNTRANSFER => true, CURLOPT_CUSTOMREQUEST => $method,
        CURLOPT_HTTPHEADER => $headers, CURLOPT_CONNECTTIMEOUT => 5, CURLOPT_TIMEOUT => 15,
        CURLOPT_FOLLOWLOCATION => false, CURLOPT_SSL_VERIFYPEER => true, CURLOPT_SSL_VERIFYHOST => 2]);
    if ($body !== null) curl_setopt($handle, CURLOPT_POSTFIELDS, json_encode($body, JSON_THROW_ON_ERROR));
    $raw = curl_exec($handle);
    $status = curl_getinfo($handle, CURLINFO_RESPONSE_CODE);
    $failed = $raw === false;
    $errorNumber = curl_errno($handle);
    curl_close($handle);
    if ($failed) throw new RuntimeException('Provider connection failed (cURL ' . $errorNumber . '); retry launch with the same idempotency key');
    $result = json_decode($raw, true, 512, JSON_THROW_ON_ERROR);
    if ($status < 200 || $status >= 300) throw new RuntimeException($result['message'] ?? 'Provider request failed', $status);
    return $result['data'];
}

function launchGame(string $baseUrl, string $apiKey, string $authenticatedPlayerId, string $returnUrl, string $idempotencyKey, string $symbol = 'wildframes', string $device = 'desktop'): array {
    if ($idempotencyKey === '') throw new InvalidArgumentException('Persist an idempotency key before launching');
    if (!in_array($device, ['desktop','mobile'], true)) throw new InvalidArgumentException('Device must be desktop or mobile');
    return providerRequest($baseUrl, $apiKey, 'POST', 'api/provider/v1/launch-url', [
        'symbol' => $symbol, 'external_player_id' => $authenticatedPlayerId, 'currency' => 'EUR',
        'lang' => 'en', 'device' => $device, 'return_url' => $returnUrl,
    ], $idempotencyKey);
}

// .NET 8+. Server-side only. Reuse this client; obtain credentials from a secret store.
using System.Net;
using System.Security.Cryptography;
using System.Text;
using System.Text.Json;
using System.Text.RegularExpressions;

public sealed class AureviaProvider : IDisposable
{
    private readonly HttpClient http;
    private readonly Uri baseUri;
    private readonly string apiKey;

    public AureviaProvider(string baseUrl, string apiKey)
    {
        baseUri = new Uri(baseUrl.TrimEnd('/') + "/");
        if (baseUri.Scheme != "https" || baseUri.UserInfo != "" || baseUri.Query != "" || baseUri.Fragment != "")
            throw new ArgumentException("Use the assigned HTTPS provider base URL.");
        if (string.IsNullOrEmpty(apiKey) || apiKey.Contains('\r') || apiKey.Contains('\n'))
            throw new ArgumentException("Invalid API key header.");
        this.apiKey = apiKey;
        http = new HttpClient(new HttpClientHandler { AllowAutoRedirect = false, UseCookies = false })
            { Timeout = TimeSpan.FromSeconds(15) };
    }

    public async Task<JsonElement> RequestAsync(HttpMethod method, string path, object? body = null,
        string? idempotencyKey = null, CancellationToken cancellationToken = default)
    {
        if (!path.StartsWith("api/provider/v1/", StringComparison.Ordinal) || path.Contains("..") || path.Contains('\\'))
            throw new ArgumentException("Invalid provider path.");
        using var request = new HttpRequestMessage(method, new Uri(baseUri, path));
        request.Headers.Add("X-Provider-API-Key", apiKey);
        request.Headers.Add("Accept", "application/json");
        if (idempotencyKey != null) request.Headers.Add("Idempotency-Key", idempotencyKey);
        if (body != null) request.Content = new StringContent(JsonSerializer.Serialize(body), Encoding.UTF8, "application/json");
        using var response = await http.SendAsync(request, cancellationToken);
        if (!response.IsSuccessStatusCode)
            throw new ProviderException(response.StatusCode, response.Headers.RetryAfter?.ToString());
        using var document = JsonDocument.Parse(await response.Content.ReadAsStringAsync(cancellationToken));
        return document.RootElement.GetProperty("data").Clone();
    }

    public Task<JsonElement> LaunchAsync(string authenticatedPlayerId, string returnUrl, string persistedKey,
        string symbol = "wildframes", string device = "desktop", CancellationToken cancellationToken = default)
    {
        if (string.IsNullOrEmpty(persistedKey)) throw new ArgumentException("Persist a key before launching; reuse it with the exact body on retries.");
        if (device != "desktop" && device != "mobile") throw new ArgumentException("Invalid device.");
        return RequestAsync(HttpMethod.Post, "api/provider/v1/launch-url", new {
            symbol, external_player_id = authenticatedPlayerId, currency = "EUR", lang = "en", device, return_url = returnUrl
        }, persistedKey, cancellationToken);
    }

    public static JsonElement VerifyCallback(string secret, byte[] rawBody, string timestamp, string signature,
        string requestId, string operation, string operatorId, long? now = null)
    {
        if (string.IsNullOrEmpty(secret) || string.IsNullOrEmpty(operatorId) ||
            !new[] { "balance", "debit", "credit", "rollback" }.Contains(operation))
            throw new ArgumentException("Wallet verifier is not configured.");
        if (!Regex.IsMatch(timestamp, @"\A[0-9]{1,12}\z") ||
            Math.Abs((now ?? DateTimeOffset.UtcNow.ToUnixTimeSeconds()) - long.Parse(timestamp)) > 300 ||
            !Regex.IsMatch(signature, @"\A[a-f0-9]{64}\z")) throw new CryptographicException("Invalid signature or timestamp.");
        using var hmac = IncrementalHash.CreateHMAC(HashAlgorithmName.SHA256, Encoding.UTF8.GetBytes(secret));
        hmac.AppendData(Encoding.ASCII.GetBytes(timestamp + "."));
        hmac.AppendData(rawBody);
        if (!CryptographicOperations.FixedTimeEquals(hmac.GetHashAndReset(), Convert.FromHexString(signature)))
            throw new CryptographicException("Invalid signature.");
        using var document = JsonDocument.Parse(rawBody);
        var payload = document.RootElement;
        if (string.IsNullOrEmpty(requestId) || payload.GetProperty("request_id").GetString() != requestId ||
            payload.GetProperty("operator_id").GetString() != operatorId || payload.GetProperty("transaction_type").GetString() != operation)
            throw new InvalidOperationException("Callback identity mismatch.");
        return payload.Clone();
    }

    public void Dispose() => http.Dispose();
}

public sealed class ProviderException(HttpStatusCode status, string? retryAfter) : Exception($"Provider HTTP {(int)status}")
{
    public HttpStatusCode Status { get; } = status;
    public string? RetryAfter { get; } = retryAfter;
}

// Java 17+ and Jackson (see pom.xml). Backend only; never expose API keys to a browser.
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import java.net.URI;
import java.net.http.*;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.time.Duration;
import java.time.Instant;
import java.util.*;
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;

public final class AureviaProvider {
    private static final ObjectMapper JSON = new ObjectMapper();
    private final HttpClient http = HttpClient.newBuilder().followRedirects(HttpClient.Redirect.NEVER)
        .connectTimeout(Duration.ofSeconds(5)).build();
    private final URI base;
    private final String key;

    public AureviaProvider(String baseUrl, String apiKey) {
        base = URI.create(baseUrl.replaceAll("/+$", "") + "/");
        if (!"https".equals(base.getScheme()) || base.getHost() == null || base.getUserInfo() != null ||
            base.getQuery() != null || base.getFragment() != null) throw new IllegalArgumentException("Use the assigned HTTPS base URL.");
        if (apiKey == null || apiKey.isEmpty() || apiKey.contains("\r") || apiKey.contains("\n"))
            throw new IllegalArgumentException("Invalid API key header.");
        key = apiKey;
    }

    public JsonNode request(String method, String path, Object body, String persistedKey) throws Exception {
        if (!path.startsWith("api/provider/v1/") || path.contains("..") || path.contains("\\"))
            throw new IllegalArgumentException("Invalid provider path.");
        var builder = HttpRequest.newBuilder(base.resolve(path)).timeout(Duration.ofSeconds(15))
            .header("X-Provider-API-Key", key).header("Accept", "application/json");
        if (persistedKey != null) builder.header("Idempotency-Key", persistedKey);
        var publisher = HttpRequest.BodyPublishers.noBody();
        if (body != null) {
            builder.header("Content-Type", "application/json");
            publisher = HttpRequest.BodyPublishers.ofString(JSON.writeValueAsString(body), StandardCharsets.UTF_8);
        }
        var response = http.send(builder.method(method, publisher).build(), HttpResponse.BodyHandlers.ofString(StandardCharsets.UTF_8));
        if (response.statusCode() < 200 || response.statusCode() >= 300)
            throw new ProviderException(response.statusCode(), response.headers().firstValue("Retry-After").orElse(null));
        return JSON.readTree(response.body()).required("data");
    }

    public JsonNode launch(String authenticatedPlayerId, String returnUrl, String persistedKey, String symbol, String device) throws Exception {
        if (persistedKey == null || persistedKey.isEmpty()) throw new IllegalArgumentException("Persist the launch key before sending; reuse it on retries.");
        if (!Set.of("desktop", "mobile").contains(device)) throw new IllegalArgumentException("Invalid device.");
        return request("POST", "api/provider/v1/launch-url", Map.of("symbol", symbol,
            "external_player_id", authenticatedPlayerId, "currency", "EUR", "lang", "en", "device", device,
            "return_url", returnUrl), persistedKey);
    }

    public static JsonNode verifyCallback(String secret, byte[] rawBody, String timestamp, String signature,
        String requestId, String operation, String operatorId, long now) throws Exception {
        if (secret == null || secret.isEmpty() || operatorId == null || operatorId.isEmpty() ||
            !Set.of("balance", "debit", "credit", "rollback").contains(operation)) throw new IllegalArgumentException("Verifier is not configured.");
        if (timestamp == null || !timestamp.matches("[0-9]{1,12}") ||
            Math.abs(now - Long.parseLong(timestamp)) > 300 || signature == null || !signature.matches("[a-f0-9]{64}"))
            throw new SecurityException("Invalid signature or timestamp.");
        var mac = Mac.getInstance("HmacSHA256");
        mac.init(new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
        mac.update((timestamp + ".").getBytes(StandardCharsets.US_ASCII));
        if (!MessageDigest.isEqual(mac.doFinal(rawBody), HexFormat.of().parseHex(signature))) throw new SecurityException("Invalid signature.");
        var payload = JSON.readTree(rawBody);
        if (requestId == null || requestId.isEmpty() || !payload.path("request_id").isTextual() ||
            !requestId.equals(payload.path("request_id").asText()) || !operatorId.equals(payload.path("operator_id").asText()) ||
            !operation.equals(payload.path("transaction_type").asText())) throw new SecurityException("Callback identity mismatch.");
        return payload;
    }

    public static final class ProviderException extends Exception {
        public final int status;
        public final String retryAfter;
        ProviderException(int status, String retryAfter) {
            super("Provider HTTP " + status); this.status = status; this.retryAfter = retryAfter;
        }
    }
}

1. Entenda a integração

Seu backend autentica o jogador, consulta os jogos atribuídos e solicita uma URL de abertura. Seu frontend abre essa URL. Sua carteira mantém o saldo oficial e implementa quatro callbacks HTTPS: balance, debit, credit e rollback. O jogo hospedado gerencia seus recursos e seu protocolo nativo.

A versão 1.0.1 é um ambiente de testes com nove jogos e duas carteiras de operadores simulados. Use somente fundos simulados. Atualmente oferece EUR e jogos em inglês, com quatro sessões simultâneas no total e duas por operador. O acesso de clientes à produção exige validação e ativação separadas. A documentação em espanhol ou português não habilita esses idiomas na API do jogo. Este serviço integra o runtime do VPS; não é a API oficial de desenvolvedores da Play’n GO.

2. Configure seu backend

Use https://aureviagaming.com/playngo-sandbox como PROVIDER_BASE_URL. Guarde OPERATOR_API_KEY no cofre de segredos do servidor. Envie x-provider-api-key em cada solicitação, ou Authorization: Bearer, usando apenas um método. Nunca coloque chaves em URLs, código frontend ou logs. A identidade do operador vem da chave; omita operator_id nas solicitações ao provedor. O segredo de assinatura da carteira é uma credencial separada.

Na integração inicial, informe as origens web, URLs HTTPS aprovadas de retorno ou lobby, URLs base dos callbacks, moedas solicitadas e contato técnico. Credenciais e configurações são separadas por ambiente. Seu servidor precisa de HTTPS/JSON, relógios sincronizados, verificação HMAC do corpo original, registros persistentes e atualizações atômicas de saldos decimais. Plataformas hospedadas devem permitir um adaptador personalizado. Sites estáticos precisam de backend; apps nativos precisam de integração testada com navegador ou WebView.

3. Consulte os jogos atribuídos

GET /api/provider/v1/games?provider_id=playngo retorna data.items com jogos atribuídos e habilitados para seu operador. GET /api/provider/v1/games/{symbol} retorna um jogo. Use os símbolos do catálogo e aceite campos de resposta desconhecidos. A disponibilidade não garante todos os recursos, idiomas ou valores de aposta. O contrato v1 não inclui endpoint para distribuir rodadas grátis promocionais.

Os símbolos preparados são wildframes, honeyrush, moonprincess, wheelofmictlan, secretofdead, legacyofegypt, hugosadventure, trollhunters2 e demon. honeyrush corresponde ao Honey Rush original; Honey Rush Black & Yellow é outro título. Não fixe a quantidade de jogos do catálogo na integração.

4. Abra o jogo para o jogador autenticado

POST /api/provider/v1/launch-url exige Idempotency-Key. O corpo JSON exige symbol, external_player_id, currency e return_url. O campo opcional lang usa en por padrão; device aceita desktop ou mobile, com desktop como padrão. Use EUR, um símbolo atribuído e uma URL HTTPS de retorno aprovada neste ambiente. Idiomas de jogo não suportados são rejeitados. Obtenha external_player_id da sessão autenticada no servidor; nunca confie diretamente em um ID enviado pelo navegador.

IDs de jogador são strings opacas de 1–128 caracteres e preservam maiúsculas, Unicode e espaços iniciais ou finais. Não remova espaços nem normalize para outra identidade. Preserve exatamente session_id, round_id, transaction_id e request_id. A versão 1.0.0 removia espaços dos IDs; repetições antigas com espaços podem retornar 409. Concilie a sessão original antes de criar deliberadamente uma nova abertura.

Salve uma chave de abertura e o corpo exato antes de enviar. Repetições idênticas retornam a resposta e a validade originais; um corpo diferente com a mesma chave retorna 409 idempotency_conflict. Guarde as chaves por pelo menos 24 horas. Após consumir ou expirar o ticket, uma nova abertura intencional exige outra chave. Um timeout não autoriza gerar outra chave.

{
  "symbol": "wildframes",
  "external_player_id": "player-123",
  "currency": "EUR",
  "lang": "en",
  "device": "desktop",
  "return_url": "https://client.example/lobby"
}

5. Abra e feche o jogo corretamente

Uma abertura bem-sucedida retorna data.launch_url, session_id e expires_at. Entregue somente a URL ao navegador autenticado correto e abra logo por redirecionamento ou iframe. O ticket é de uso único e vale por 60 segundos. Use título no iframe, permissão de tela cheia, política no-referrer e altura responsiva. Sua CSP frame-src deve permitir a origem do jogo; o provedor também precisa aprovar sua origem para incorporação. Teste dispositivos móveis e cookies de terceiros bloqueados. CORS não controla a incorporação de iframes.

Uma sessão dura até 30 minutos de inatividade ou quatro horas no total. Uma reconexão de rede na mesma página carregada usa outra credencial de sessão. Recarregar a página, reiniciar o navegador ou reabrir uma URL copiada exige nova abertura. Feche a sessão anterior com POST /api/provider/v1/sessions/{session_id}/close e solicite outra com nova chave. O fechamento pode ser repetido e bloqueia novas jogadas, preservando pagamentos e reembolsos aceitos. Tickets não usados reservam capacidade até expirar. Voltar ao lobby não comprova que a liquidação terminou.

6. Verifique os callbacks da carteira

Implemente POST /balance, /debit, /credit e /rollback na URL base configurada da carteira. O provedor envia content-type: application/json, x-pp-request-id, x-pp-timestamp (segundos Unix) e x-pp-signature. Calcule HMAC-SHA256 hexadecimal em minúsculas sobre ASCII(timestamp) + um ponto + o corpo UTF-8 original exato, usando o segredo da carteira. Compare em tempo constante e rejeite diferenças de horário maiores que 300 segundos. Preserve os bytes antes de qualquer middleware JSON; analisar e serializar novamente altera a assinatura.

Após verificar a assinatura, analise o JSON e exija que o ID da solicitação no cabeçalho corresponda a request_id, operator_id ao operador configurado e transaction_type ao endpoint. Valide a titularidade do jogador e da sessão e todo o esquema antes de acessar o livro contábil. Repetições usam novos timestamps, assinaturas e IDs de solicitação, preservando o ID da transação e os campos financeiros. O fixture determinístico para download testa as quatro linguagens sem contatar uma carteira.

HMAC-SHA256(wallet_secret, ASCII(timestamp) + "." + raw_request_body)

7. Aplique o contrato da carteira

Valores e saldos são strings decimais com exatamente duas casas, como "2.00". Use unidades menores inteiras ou um tipo decimal; nunca aritmética binária de ponto flutuante. As moedas habilitadas usam duas casas, sem conversão cambial automática. Os campos comuns são operator_id, player_id, session_id, game_symbol, currency, request_id, transaction_id, transaction_type, action_type e amount. O esquema OpenAPI define os tipos e limites exatos.

Balance usa amount "0.00" e action_type balance, sem campos de rodada. Debit exige valor positivo, round_id e round_closed false. Credit exige round_id e round_closed, permite zero e encerra a rodada no crédito final. Rollback exige valor positivo, round_closed true e original_transaction_id. Várias etapas ou rodadas grátis podem compartilhar uma rodada; elimine duplicatas por transação, nunca apenas por rodada. action_type é descritivo e não substitui transaction_type.

Retorne HTTP 200 com success true, o saldo oficial, currency e transaction_id correspondentes. Rejeições de negócio válidas usam HTTP 200 com success false e erros como insufficient_funds, unknown_player, currency_mismatch, player_blocked ou transaction_cancelled. Use 401 para assinaturas inválidas ou timestamps antigos; 403 para titularidade inválida; 400 para dados inválidos; 409 para identidade de transação conflitante; 503 para falha temporária. Retorne JSON UTF-8 sem compressão em cinco segundos, com no máximo 65.536 bytes; nunca uma página HTML de erro.

{"success":true,"balance":"98.00","currency":"EUR","transaction_id":"txn_debit_example_01"}

8. Garanta um único efeito financeiro

Em cada ambiente e operador, registre um transaction_id único com uma impressão dos campos de jogador, sessão, jogo, rodada, tipo, ação, moeda, valor, fechamento da rodada e referência ao débito original. Exclua IDs de entrega e timestamps. Em UMA transação de banco: registre ou confira o ID, bloqueie ou atualize atomicamente a carteira, valide fundos e moeda, salve o lançamento e a resposta imutável e confirme. Duplicatas simultâneas devem obter o mesmo resultado salvo. Guarde também rejeições definitivas; alterar campos financeiros com o mesmo ID gera idempotency_conflict.

Um callback financeiro bem-sucedido repetido retorna o saldo e a resposta ORIGINAIS salvos, mesmo que outras transações tenham alterado a carteira. Nunca aplique duas vezes. Outra solicitação balance consulta o saldo atual. Guarde registros de deduplicação e cancelamento enquanto houver possibilidade de repetição ou conciliação; registros pendentes não devem expirar. A política de retenção e arquivo é acordada na integração inicial.

9. Trate cancelamentos e recuperação

Rollback referencia o débito original por original_transaction_id. Valor, moeda e titularidade devem corresponder. Se o débito existe e não foi cancelado, reembolse uma vez; se já foi cancelado, responda com sucesso sem outro reembolso. Se não existe, salve uma marca de cancelamento e responda com sucesso sem alterar fundos; rejeite qualquer débito posterior com esse ID. Serialize tanto o ID do rollback quanto o do débito original para impedir reembolsos duplicados por tentativas diferentes. Nunca reverta um crédito não relacionado.

Uma resposta desconhecida pode significar que a carteira confirmou antes da falha de conexão. Pause o jogo diante de débito desconhecido e resolva a mesma transação ou cancele por rollback. Mantenha créditos e reembolsos pendentes até confirmar; repetições preservam seus IDs. O provedor usa espera progressiva com variação (aproximadamente 1, 5, 15 e depois 60 segundos), verificada a cada cinco segundos, com obrigações persistentes. Continue liquidando créditos e reembolsos aceitos após fechar o navegador ou expirar a sessão. Uma rodada revelada com prêmio não pode ser cancelada para evitar o pagamento. Rodadas aceitas encerradas são coletadas automaticamente após dois minutos de inatividade; gamble está desabilitado nesta versão.

10. Consulte sessões e transações

GET /api/provider/v1/transactions?limit=50 lista as transações do operador da mais recente para a mais antiga. O tamanho de página é de 1–100. Envie data.next_cursor sem alterar como cursor para a próxima página; o cursor tem limite de 2.048 caracteres. GET /api/provider/v1/transactions/{transaction_id} retorna operação, valor, moeda, IDs de rodada e sessão, status, número de tentativas e último erro. GET /api/provider/v1/sessions/{session_id} retorna metadados com controle de titularidade. Codifique IDs opacos como segmentos individuais da URL.

pending, sending e unknown ainda estão em resolução: não crie transações financeiras substitutas. success foi confirmado pela carteira; rejected é uma rejeição definitiva de débito ou saldo; cancelled indica débito pendente cancelado por rollback. Um débito bem-sucedido reembolsado mantém success com cancelled_by_rollback e um rollback bem-sucedido separado. Créditos e reembolsos rejeitados continuam pendentes de recuperação e atenção do operador.

11. Trate erros e capacidade

Erros do provedor contêm success false, error, message e request_id. Em 400/422 corrija dados ou moeda e idioma não suportados; 401 corrija credenciais; 403 confira permissões do operador, jogo e origem; 404 atualize o catálogo ou verifique o recurso; 409 concilie a chave de abertura conflitante. Em 429 respeite Retry-After. Em 502/503 ou timeouts de rede, aguarde e repita com a chave e o corpo originais salvos. Solicitações GET podem ser repetidas. Guarde IDs de solicitação sem segredos para suporte.

O limite do ambiente é de 60 solicitações ao provedor por minuto e operador, excluindo jogo e callbacks enviados. Os corpos aceitam 65.536 bytes e dez segundos (413 por tamanho, 408 por timeout). 503 capacity_reached e 503 maintenance incluem Retry-After: 5; aguarde e repita a mesma chave. A manutenção bloqueia novas apostas enquanto pagamentos e reembolsos aceitos continuam. Quatro sessões no total e duas por operador são limites de admissão, não capacidade de grande volume. Uma página de verificação de navegador não é uma resposta da API: informe-a com o ID em vez de desabilitar TLS ou expor credenciais no navegador.

12. Teste antes de ativar clientes

Execute primeiro os testes de assinatura offline incluídos. Depois teste catálogo e autenticação, isolamento de jogadores, validade e reutilização de abertura, iframes em desktop e dispositivos móveis, todos os callbacks, duplicatas simultâneas, timeout após confirmar, rollback antes do débito, saldo insuficiente, recuperação de créditos e reconexão durante recursos. Concilie débitos aceitos com créditos finais ou cancelamentos confirmados. Um health check ou demo funcional não certifica uma carteira cliente.

A ferramenta retomável wallet-conformance.mjs exige Node.js 20+, um jogador de testes dedicado e inativo e pelo menos EUR 1.00 simulados. Copie a configuração de exemplo para um arquivo privado e execute com um diário privado. Suas 17 verificações deixam alteração líquida de saldo zero ao concluir. Após falha de conexão, retome com a MESMA configuração e diário; nunca apague o diário ou altere IDs para repetir. Mantenha segredos, diários financeiros e fundos reais fora do pacote público. As demos públicas usam saldos de visitantes isolados que começam com 10.000,00 EUR. São independentes dos jogadores de integração e dos testes de aceitação; o laboratório desativado exige acesso da equipe.

13. Versionamento e suporte

/api/provider/v1 e playngo-callback-v1 identificam os contratos; a versão de software 1.0.1 é separada. Campos opcionais e jogos podem ser adicionados; ignore campos de resposta desconhecidos e atualize o catálogo. Alterações incompatíveis de campos, assinatura ou semântica financeira exigem outro contrato versionado e migração acordada. Guarde OpenAPI aceito, diário de validação, origens, moedas, jogos e limites atribuídos e resultados de navegador com sua versão. Credenciais de testes nunca se tornam de produção ao trocar a URL.

Para suporte técnico, informe ambiente, horário UTC, símbolo do jogo, IDs de sessão, rodada e transação, ID da solicitação do provedor e erros sem segredos pelo canal acordado. Nunca compartilhe chaves da API, segredos de assinatura ou URLs ativas de abertura. Alertas do operador e ativação de produção são etapas separadas da integração inicial.
